# 클로드 구현 요청 · 금오와 월백

**태양·달 전설 서사와 투명 캐릭터 원본 / 게임 반영 대기**. 기준 68b9677의 기존 1~3장을 먼저 읽는다.

## 먼저 볼 자료

[특징·미술 기준](character-specs.md), [이야기·조우·선택 의뢰](story-plan.md), [구조 데이터](story-data.json), [원본 목록](asset-manifest.json), [점검 결과](validation.md).

## 최종 디자인 기준

초기 모델·중간 시안·배경 포함 시안은 제작 참고와 선택 목록에서 제외한다. asset-manifest.json의 canonicalAssets 네 장을 유일한 외형 기준으로 사용한다.

현재 게임의 mons.js에 남아 있는 초기 DRAW.geumo는 교체 대상이다. 최종 원본 적용 시 전투·도감·미니·대체 렌더 경로까지 함께 갱신하고, 초기 그림으로 되돌아가는 선택·대체 표시를 남기지 않는다. 이번 정리는 기획 자료에 대한 것으로 실제 게임 렌더 교체는 구현 대기다.

## 그림 적용

- assets/geumo-front.png: 금오 사선 정면(왼쪽을 봄).
- assets/geumo-back.png: 금오 후면(오른쪽 위를 향함).
- assets/wolbaek-front.png: 월백 사선 정면(왼쪽을 봄).
- assets/wolbaek-back.png: 월백 후면(오른쪽 위를 향함).

네 파일은 캐릭터만 있는 고해상도 투명 PNG다. 배경 태양·달·구름·산을 게임에 전부 재현하라는 요청이 아니다. 몸 가까운 불꽃·달빛과 자연 문양은 캐릭터 정체성에 속한다.

앞/뒤를 단순 좌우 반전으로 대신하지 않는다. 작은 전투 그림/미니는 긴 날개·꼬리·세 발, 아홉 꼬리·은빛 문양을 남겨 별도로 정리한다. 큰 원본을 그대로 축소해 뭉개진 상태를 도트 완성으로 표시하지 않는다. 이미지 알파를 보존하고 흰색/검은색 바탕에 합성하지 않는다. 낮은 알파의 가장자리 잔색을 실제 배경 위에서 확인하고, 월백의 달불은 별도 효과로 얹는다. 겹친 아홉 꼬리는 작은 그림에서 하나씩 읽히도록 정리한다.

기존 mons.js·sprites.js·dev/sprites 흐름을 확인해 알맞게 편입한다. 긴 꼬리 때문에 전체 프레임 중심과 본체 중심이 다를 수 있다. 원본을 보고 피벗·표시 영역·여백을 조정하고, 프레임에 맞추겠다고 날개/꼬리를 자르거나 짧게 바꾸지 않는다.

## 종과 데이터

금오는 기존 geumo·#909·불/비행·세 발을 유지하며 옛 둥근 그림을 새 원본 기준으로 교체한다. 기존 능력치·기술·실제 보유/포획 기록을 미술 변경 때문에 초기화하지 않는다. geumo2나 새 일반 도감 번호로 복제하지 않는다.

월백은 가칭, 에스퍼/고스트 방향이다. wolbaek은 제안 key, 정규 도감 번호는 미배정이다. 현재 #103 이후 일반 종이나 숨김 #901~909를 임의로 덮어쓰지 않도록 번호 정책을 먼저 정리한다. 최종 능력치/학습표는 현재 기술과 실제 6관장 완료 파티로 확인해 정한다. 신종 타입·특성·밤 시각 시스템을 전제로 하지 않는다.

현재 D.DEX의 hidden 필터와 개발자 미리보기는 별개로 확인한다. 일반 계정도 전설을 발견/기록/포획할 수 있어야 하며 다른 숨김 개체를 한꺼번에 공개하지 않는다. 먼 그림자·소문만 보고 caught를 켜지 않는다.

## 서사 적용

LG_S01~08의 짧은 장면/선택 대화, LQ01·02, LGZ01 햇귀절벽·LGZ02 월은못을 추가한다. 기존 q00~q33·배지·ch3_end·SQ3-05·07을 새 전설 의뢰와 묶어 잠그지 않는다. 기존 맵은 생성 템플릿과 생성기를 함께 고친다.

두 전설은 서로 적대하는 선악이 아니며 낮의 길/밤의 귀로라는 대칭이다. 시설 사고 원인과 주민의 복구 역할은 기존대로 보존한다. 포획 또는 두 의뢰 완료를 본편 열쇠로 사용하지 않는다.

각 성역은 6배지 뒤 F09로 접근하고 무료 지원 동료를 사용할 수 있다. 소문을 빠뜨렸어도 현장 일지·탁본·NPC 회상으로 시작할 수 있다. 현실 새벽·밤·만월·소유자 계정·전용 큐브를 요구하지 않는다.

## 저장·재도전

전설별 heard/trace/sighted/storyComplete/trialReady/captured를 필요한 만큼 분리하고 기본값을 미발견으로 둔다. 기존 G.S 전체를 덮어쓰지 않는다.

관찰은 서사 완료, 전투·포획은 선택이다. 큐브가 없어도 관찰/물러남과 메인 진행은 가능하다. 쓰러뜨림·도망·전멸로 전설을 영구 소멸시키지 않고 회복 후 입구에서 재도전한다. 긴 첫 장면은 반복하지 않는다.

포획 성공을 파티/보관함·도감·captured에 함께 반영하고 이벤트 자동저장도 같은 상태를 담게 한다. 저장당 1회 포획이며 방생/보관함 이동 뒤 본체가 중복 생성되지 않는다.

기존 3장 완료 저장은 새 게임·이전 컷신 순회·3장 엔딩 재생 없이 조사에 접근한다. 실제 금오 소유 저장은 중복 없이 이전하지만 개발자 미리보기만으로 소유했다고 추정하지 않는다.

## 구현 순서와 확인

1. 네 원본·현재 출력 방식과 앞/뒤 대응을 확인하고 도트·미니·피벗을 적용.
2. 금오 기존 정체성/저장과 월백 번호·타입·기술을 연결.
3. 기존 1~3장 장면·회상·두 선택 성역·지도 발견을 추가.
4. 관찰/포획 분리·일반 계정·재도전·구버전 저장을 검증.
5. 소리 끔·모바일·장면 건너뛰기·지도/물판/구조·도감 실루엣·최초 포획을 확인.

실제 실행할 항목: 새 게임, 기존 ch3_end 저장 세 종, 모든 전설 장면 생략, 두 의뢰의 다른 순서, 관찰만 완료, 큐브 없이 물러남, 도망/쓰러뜨림/전멸/재도전/포획/방생, 저장 코드 왕복, 기존 1~3장 회귀. 전설 전투 수치는 실제 파티와 레벨·회복/큐브 소비를 기록한다.

이번 묶음의 점검은 원본·알파·문서 참조·조건에 대한 것이다. 실제 게임 적용이나 전투 검증을 완료했다고 표시하지 않는다. 후속 본부·최종장 세부는 별도 기획이다.
